What the XRP Ledger records

One signature from a wallet you already have.

A dApp on Flare describes what it wants. The user signs a single XRPL payment — no bridge, no gas token, no second wallet. The ledger carries 42 bytes.

opcode · wallet · fee commitment, 32 bytes

Every square to the right is a byte of the operation. The ledger carries one byte in 24.

What actually runs—

Sealed. Every cell is one byte of the operation. It travels to the executor, never to the XRP Ledger — which sees only its hash.

Run it

Sign once. Watch two calls land on Flare.

The batch is approve then deposit — the thing one signature makes possible and a plain bridge does not. The executor is a separate actor: it notices the payment and finishes the job on its own.

The whole integration

A dApp that has never heard of the XRP Ledger.

const req = await onesig.prepare({
  xrplAddress,
  calls: [
    { target: fxrp,  data: encodeFunctionData({ abi, functionName: "approve", args: [vault, amount] }) },
    { target: vault, data: encodeFunctionData({ abi, functionName: "deposit", args: [amount] }) },
  ],
  label: "Deposit 10 mFXRP into MockVault",
  netMintUBA: 1_000_000n,
});

// req.xrplPayment is signable. The user never sees a memo.
